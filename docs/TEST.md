바꾼 게 제대로 들어갔는지 확인하는 절차입니다. 자동 2단계 + 눈으로 보는 3단계.

```powershell
cd D:\workspace\carbon-biz
```

## 자동 1 · 데이터 파이프라인 (필수)

```powershell
python tests\test_data.py
```

48개 항목을 검사하고 마지막에 `통과 48 / 실패 0`이 나오면 됩니다.
하나라도 `FAIL`이면 그 줄에 기대값과 실제값이 같이 찍힙니다.

**무엇을 보는가**

| 묶음 | 검사 내용 |
|---|---|
| 원본 대조 | 원본 CSV 행 수 == 분류 결과 행 수 (누락 없이 다 처리됐는지) |
| 분류 무결성 | 업종·단지유형·열공정 각각의 합계가 전체와 일치, 공백 없음 |
| 주소 파싱 | 시도 미상 2% 미만, 미상의 대부분이 실제로 빈 주소인지 |
| 단지유형 정합 | 단지명이 있으면 개별입지가 아니고, 없으면 개별입지인지 |
| 분류 스팟체크 | `시멘트→비금속광물`, `알루미늄괴→1차금속·용해소성` 등 10개 케이스 |
| 오분류 방지 | `태양광발전장치`가 CBAM이 아닌지, `요소수`가 비료가 아닌지, `과산화수소`가 수소가 아닌지 |
| data.json | 건수 일치, 시도 17개, 필드 완비, 16MB 미만 |
| My Maps | 파일 수, 2,000행 한도, 위치·이름 열 존재 |
| 생성 페이지 | 데이터 임베드, 확대 코드 포함, JSON 파싱 가능 |

**분류 규칙을 고쳤다면 스팟체크를 같이 고치십시오.** `6_test.py`의 `SPOT` 목록이
"이 생산품은 이 업종이어야 한다"는 계약입니다. 규칙을 바꿔 이게 깨지면
의도한 변경인지 사고인지 판단해야 합니다.

## 자동 2 · 화면 동작 (권장)

```powershell

npx playwright install chromium
node tests\test_ui.js
```

브라우저를 띄워 실제로 클릭하고 확인합니다. `통과 20 / 실패 0`이 목표입니다.

**무엇을 보는가**

- 상단 지표 4개, 지도 렌더, 시도 막대 17개, 두 표가 채워졌는지
- **업종 선택** → 건수가 줄고, 기업 표가 그 업종만 나오는지
- **단지유형 조합** → 추가로 좁혀지고, 표가 전부 그 유형인지
- **열공정·CBAM 칩**, **검색**, **시도 막대 클릭**
- **확대 버튼 / 원래대로 / 휠 확대**가 실제로 `transform`을 바꾸는지
- JS 오류 0건

외부 폰트(Google Fonts) 로딩 실패는 검사에서 제외했습니다. 사내망이나 오프라인에서는
웹폰트만 대체되고 기능은 그대로 동작하기 때문입니다.

## 눈으로 1 · 지도 페이지

```powershell
Start-Process index.html
```

| 확인 | 기대 |
|---|---|
| 휠을 굴린다 | 커서 위치를 중심으로 확대된다 |
| 지도를 끈다 | 따라 움직인다 |
| `⟲` 버튼 | 원래 배율로 돌아온다 |
| 업종에서 `식품·음료` 선택 | 지도 원 크기와 아래 표가 함께 바뀐다 |
| 단지유형에서 `농공단지` 선택 | 전남·전북·경북 비중이 커진다 (농공단지 특성) |
| 열공정 `용해·소성` | 경기·경남·경북에 몰린다 |
| 산업단지 표에서 아무 단지 클릭 | 아래 기업 목록이 그 단지로 좁혀진다 |
| 초기화 | 모든 필터와 배율이 풀린다 |

숫자 하나는 직접 대조해보시길 권합니다. 업종을 `1차 금속`으로 놓고
상단 "타깃" 수치와 `전체공장_분류결과.csv`를 엑셀에서 `업종 = 1차 금속` 필터한 건수 중
CBAM 또는 열공정이 있는 행 수가 맞는지 보면 파이프라인 전체가 검증됩니다.

## 눈으로 2 · Google My Maps

**작은 것부터 하십시오.** 14행짜리로 먼저 확인하고 큰 파일로 갑니다.

1. https://mymaps.google.com → `새 지도 만들기`
2. `가져오기` → `mymaps/00_산단공_거점.csv`
3. 위치 열 = `주소`, 제목 열 = `이름`
4. **핀 14개가 대구·서울·인천·안산·구미·달서·광주·여수·창원·천안·군산·부산·울산·원주에 찍히면 정상**

여기까지 되면 나머지 파일도 같은 방식으로 됩니다.

| 확인 | 기대 |
|---|---|
| `01_국가산업단지.csv` (위치 열 = `검색주소`) | 38개 핀, 시화·반월·남동·창원·구미 등 |
| 가져오기 후 경고 문구 | "위치를 찾을 수 없음"이 몇 건인지 확인 |
| 레이어 스타일 → 균일 스타일 | 거점은 빨강 별, 국가산단은 파랑 공장 아이콘 |
| 레이어를 드래그해 위로 | 거점 핀이 공장 점 위에 그려진다 |

**위치 실패가 10%를 넘으면** 주소 정제가 필요한 것이므로,
`2_geocode.py`로 좌표를 먼저 만든 뒤 `위도`·`경도` 열로 올리는 편이 낫습니다.

## 눈으로 3 · 분류 품질 (표본 검사)

자동 테스트는 "규칙대로 돌아가는가"만 봅니다. **"규칙이 맞는가"는 사람이 봐야 합니다.**

엑셀에서 `전체공장_분류결과.csv`를 열고 관심 업종을 필터한 뒤
**무작위 30건 정도의 `생산품`과 `업종`을 눈으로 대조**하십시오.

특히 볼 곳:

- `기타 제조` 55,442건 — 여기 있는 것 중 실제로는 특정 업종인 게 얼마나 되는지
- `1차 금속` vs `금속가공` 경계 — 용해를 하는 곳과 가공만 하는 곳이 갈렸는지
- `열공정 = 용해·소성` 4,202건 — 정말 고온 공정을 쓰는 곳인지

오분류를 찾으면 `1_prep.py`의 `SECTORS` / `HEAT`에 키워드를 추가하고,
`6_test.py`의 `SPOT`에 그 케이스를 추가한 뒤 1 → 3 → 4 → 5단계를 다시 돌리십시오.
같은 실수가 다시 들어오지 않게 됩니다.
